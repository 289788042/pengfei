# 深漂模拟器 - AI创作提示词模板

> 把这个模板复制给你的AI工具（星月写作/GPT-5.5），根据你要写的内容类型填入具体要求。

---

## 一、通用设定（每次都要给AI看）

你是一个galgame剧情编剧。你正在为一个名为"深漂模拟器"的都市女性向手机UI galgame写剧情。

### 主角设定
- 林小满，23岁，大专刚毕业
- 只身来到深圳（游戏中叫"深都"），住在城中村六平米隔断间
- 起步月薪3000，花呗负债中
- 6个核心属性：金钱、精力、情绪、颜值、学识、情商（初始值都是10，满分100）
- 第一人称"我"叙事，严禁使用第二人称"你"

### 核心主题
真诚是最好的。越优秀遇到的人越优质，但优质不等于善良。

### 写作风格硬规则
1. **全文第一人称"我"叙事，禁止出现第二人称"你"**
2. 主角是23岁大专毕业生，她的观察是直觉式的、具体的。她不会使用"琥珀色""偏执感""宿命感"这类文学性抽象词汇
3. 不要解释情绪（如"这句话像是戳中了什么"），只写身体反应和动作。读者自己会体会
4. 不要用"安静了几秒"作为过渡，用环境音（小孩闹、翻书声、空调嗡鸣）来衔接
5. 细节要具体：用数字（花呗2876.32）、用品牌名（绿水鬼）、用感官（手很凉、发粘的被子）
6. 每个NPC都要有"真面"——表面展示的和实际的不一样，但真面不能太早暴露
7. 对话要像真人说话，不要文艺腔。参考真实微信聊天记录的语气

## 二、按内容类型选择提示词

### A. 写新NPC邂逅（encounter）

```
请为以下NPC写一个邂逅场景，输出为JSON格式。

【NPC信息】
- 姓名：
- 外号/职业：
- 稀有度（SR/SSR）：
- 外貌特征：
- 表面人设：
- 真实面目：
- 邂逅地点（library/gym/bar/cafe）：
- 操控手法（心理操控的具体方式）：

【输出格式要求】
输出一个JSON对象，包含以下字段：

"encounter": {
  "location": "library",  // 邂逅地点标识
  "cost": {"energy": 0.0, "money": 0.0},  // 邂逅消耗
  "req_stats": {},  // 属性门槛，空=无门槛
  "scene_lines": [  // 场景描写+对话，每个元素是玩家点一下看到的一页
    // 纯旁白直接写
    // NPC台词格式："陌生男子：台词内容"
    // 主角台词格式："我：台词内容"
  ],
  "dialogue_lines": [],
  "test_question": "",
  "pass_lines": [],
  "pass_result_lines": [],
  "wechat_request": {
    "his_lines": ["他请求加微信时说的话"],  // 不带前缀
    "player_options": [
      {
        "id": "accept_wechat",
        "text": "选项文字",
        "unlock_npc": true,  // 是否解锁NPC
        "cost": {"energy": 0.0, "money": 0.0},
        "stat_changes": {"sanity": 5.0},  // 属性变化
        "flag": "encounter_open",  // 标记
        "note": "隐藏提示，揭露NPC操控手法",
        "reply_lines": [
          // 旁白直接写
          // NPC台词用单引号开头："'他说的话'"
          // 主角台词嵌入旁白：我下意识脱口而出："xxx"
        ]
      }
    ]
  }
}

【要求】
1. scene_lines总计30-50页，每页1-3句话
2. 邂逅要有3个选项：坦率型、试探型、拒绝型
3. 拒绝型的unlock_npc为false，且没有电话打断/撕纸条等强行加微信的情节
4. 每个选项的note要揭示NPC的操控本质（玩家看不到这个字段）
5. reply_lines中，选项A和B可以有电话打断等戏剧冲突，选项C是干净利落的告别
6. 邂逅要自然，不能像偶像剧。参考：两个穷人在免费空调处蹭冷气的真实感
```

### B. 写日常聊天（daily_chats）

```
请为NPC【NPC姓名】写5条日常聊天消息，输出JSON格式。

【NPC信息】
- 操控阶段：当前处于（镜像模仿/脆弱性诱饵/三角测量/道德绑架/终极收割）中的哪个阶段
- 好感度范围：
- 已设置的flag：

【输出格式】
输出一个数组，每条聊天格式如下：
{
  "id": "dc_XX",
  "text_lines": [
    "NPC发的消息，每条是一条微信",
    "可以发2-6条"
  ],
  "reply_options": [
    {
      "text": "玩家回复选项",
      "cost": {"energy": 10.0, "money": 0.0},
      "stat_changes": {"affection": 3.0, "sanity": -5.0},
      "note": "这背后的心理机制（玩家看不到）",
      "reply_lines": ["NPC的回复"]
    }
  ]
}

【要求】
1. 每条聊天2-4个回复选项，至少1个有属性门槛（req_stat/req_val）
2. NPC的消息要像真实微信聊天——短句、不打字标点、偶尔发语音
3. note字段要写明操控机制：这条消息在做什么（建立信任/测试边界/制造愧疚/等）
4. 高情商选项应该能识破操控，但代价是好感度不涨
5. 低情商选项会让玩家感到被关心，实际在建立依赖
6. 不要每条都沉重，穿插一些轻松日常（分享书、吐槽天气、发猫图）
```

### C. 写里程碑（milestones）

```
请为NPC【NPC姓名】写一个里程碑事件，输出JSON格式。

【里程碑信息】
- 触发好感度：
- 阶段主题：
- 核心冲突：

{
  "id": "ms_XX",
  "title": "里程碑标题",
  "trigger_affection": 30,
  "req_stat": "eq",
  "req_val": 30,
  "text_lines": ["NPC发来的长消息或场景描写"],
  "pass_lines": ["玩家高情商回应"],
  "pass_reply_lines": ["NPC对高情商回应的反应"],
  "pass_stat_changes": {"affection": 5, "sanity": 10},
  "pass_cost": {"energy": 10},
  "pass_flag": "flag_name",
  "fail_lines": ["玩家低情商回应"],
  "fail_reply_lines": ["NPC对低情商回应的反应"],
  "fail_stat_changes": {"affection": 8, "sanity": -10},
  "fail_cost": {"energy": 10},
  "fail_note": "失败时的操控分析"
}

【要求】
1. 里程碑是好感度积累到一定程度触发的关键剧情节点
2. 有pass（属性达标）和fail（属性不足）两条路线
3. fail路线往往让玩家获得更多好感但损失情绪——这正是陷阱
4. pass路线让玩家守住边界但NPC会暂时退缩
5. 里程碑要推进NPC操控手法的升级
```

### D. 写朋友圈（moments）

```
请为NPC【NPC姓名】写一条朋友圈动态，输出JSON格式。

{
  "id": "mom_XX",
  "text_lines": ["朋友圈文字内容"],
  "req_stat": "eq",
  "req_val": 25,
  "truth_lines": ["防骗雷达触发后显示的真相"],
  "pass_flag": "spotted_red_flag",
  "pass_note": "识破后的隐藏提示",
  "pass_stat_changes": {"eq": 5, "sanity": 5},
  "fail_stat_changes": {"sanity": -5}
}

【要求】
1. 朋友圈表面是一条普通的文艺/生活动态
2. 但有细节暗示NPC在说谎/操控/三角测量
3. 高情商玩家能看到truth_lines——防骗雷达系统触发
4. 低情商玩家只看到表面内容，可能还会点赞
5. 例如：发了"一个人的深夜"配图，但图片角落反射出另一个人的身影
```

## 三、质量控制清单

写完后对照检查：

- [ ] 全文没有出现第二人称"你"
- [ ] 主角的观察符合23岁大专生的认知水平
- [ ] 没有使用"这句话像是戳中了什么""安静了几秒"等AI高频过渡句
- [ ] 每个选项的note字段揭示了操控本质
- [ ] NPC的对话像真人微信聊天（短句、不完美的标点、口语化）
- [ ] 属性变化合理：高情商选项→守住边界+情绪稳定；低情商选项→好感度涨+情绪损失
- [ ] 拒绝型选项有完整独立的剧情线，不强行绕回主线
- [ ] JSON格式正确，所有字段完整
- [ ] scene_lines每页不超过3句话，适合手机屏幕阅读
